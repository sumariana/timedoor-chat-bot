2. Project Overview

What are you building?

Building an AI-powered Discord chatbot that centralizes project information for Timedoor by integrating with Notion using a hybrid approach: structured project metadata is retrieved via the Notion API, while unstructured or free-form pages (credentials, docs, notes) are navigated using the Notion MCP (Model Context Protocol). The bot enables team members (PMs, Developers, QA, CS, and Sales) to query project details — such as tech stacks, project URLs, open bug counts, server credentials, and release versions — directly within Discord using natural language or via private Direct Message (DM), eliminating manual search and scattered documentation overhead.

3. Business Problem

What problem does it solve? Who experiences it? Why is it important?

Currently, project information at Timedoor is scattered across various Notion pages and databases. Team members across multiple departments waste valuable time manually searching for routine project details or repeatedly escalating questions to colleagues. This disorganization creates communication bottlenecks, slows down issue resolution, and delays responses to client inquiries.

4. Solution Overview

How will it solve the problem?

Timedoor Project Assistant Bot connects Discord with Notion using a dual-source retrieval strategy. When a user asks a question — either by @mentioning the bot in a configured channel or by sending it a private Direct Message — the bot parses the intent, routes the query to the appropriate Notion data source, and synthesizes a clear natural language response via Gemini 2.0 Flash.

Structured data (project properties, bug counts, changelogs) is fetched directly via the Notion API for speed and accuracy. Unstructured content (credentials pages, design docs, free-form notes) is handled via the Notion MCP Server, which allows the AI to navigate and read pages intelligently without requiring manual structuring.

Responses are delivered in the same language as the user's query (Indonesian or English), with short-term session memory so follow-up questions resolve naturally. Sensitive fields such as passwords and API tokens are never displayed in Discord — only the host/URL is shown, with a direct link to the full Notion credentials page.

7. Scope (1-Month MVP)

Included Features:

Feature List Platform / Tech Stack

1. Natural Language Project Query Module — query tech stack, project URL, bug counts, server info, PM, release version via @mention in Discord channels or private DM


2. Live Data Fetching Module — open bug counts by environment, task list status, latest changelog version


3. Dual-Source Notion Integration & Response Caching — Notion API for structured data; Notion MCP Server for unstructured pages. Per-data-type cache TTL: project properties 30 min, bug counts 5 min, change log 15 min, credentials no-cache, doc links 60 min


4. Channel & DM Access Configuration — backend-configurable allow/deny channel list via YAML config file; DM support with server membership verification to restrict access to Timedoor staff only


5. Credential Partial Reveal Policy — bot surfaces host/URL only; raw passwords, tokens, and API keys are never displayed in Discord; full credentials link to Notion is appended


6. Bilingual Support — bot detects query language (Indonesian or English) and responds in the same language


7. Stateful Conversation Context — retains last 3–5 exchanges per user session (30-minute timeout) so follow-up questions resolve without repeating the project name

8. MVP Success Criteria

How will success be measured?

Response Latency (Structured): Bot delivers accurate responses for structured queries (tech stack, PM, bug counts, status) within 7 seconds.


Response Latency (Unstructured): Bot delivers responses for unstructured page queries (credentials, docs, notes) via Notion MCP within 15 seconds.


Data Accuracy: Achieves ≥ 90% factual accuracy on structured project data and ≥ 70% on unstructured page content, verified against live Notion sources.


Time Efficiency: Reduces average time spent looking up project information by at least 40% across participating teams.


Monthly LLM Cost: Keeps monthly AI API costs under $10 USD through structured API fast-path prioritization and response caching.


User Adoption: Weekly active usage by team members across PM, Dev, QA, CS, and Sales roles during the trial period.

9. Risks & Assumptions

Only 5 bullets maximum.

  1. Risk 1 (Data Incompleteness): If required Notion Database properties are left empty by PMs, the bot will report missing data rather than guess. Mitigated by a pre-launch Notion cleanup task owned by each team's PM.
  2. Risk 2 (API Rate Limits): High concurrent requests to the Notion API may cause minor response delays. Mitigated by the per-data-type caching layer that reduces repeat API calls.
  3. Risk 3 (Token Cost Control): Unoptimized prompt sizes could raise LLM costs as Notion data volume grows. Mitigated by prioritizing the structured Notion API fast path for common queries and using MCP only as a fallback for unstructured content.
  4. Risk 4 (Unauthorized DM Access): External users outside Timedoor may attempt to query internal project data by DMing the bot directly. Mitigated by enforcing a server membership check before processing any DM — non-Timedoor members receive a rejection message with no data exposed.
  5. Risk 5 (User Habit Persistence): Team members continuing old habits of asking colleagues directly instead of querying the Discord bot. Mitigated by an awareness campaign at launch and deploying the bot in existing team channels to minimize friction.

AI Capability

Uses a structured query-synthesis pipeline powered by Google Gemini 2.0 Flash. The bot interprets natural language queries from Discord, routes each intent to the appropriate Notion data source (Notion API for structured databases, Notion MCP Server for unstructured pages), and synthesizes the retrieved data into clear, human-readable answers. The LLM is explicitly instructed to answer only using the provided data and never invent information not present in the source — preventing hallucination on internal project details.

Business Purpose:

To convert Timedoor's Notion project databases into an interactive, conversational assistant accessible directly within Discord. This minimizes internal search time, eliminates repetitive context-switching, and streamlines cross-departmental communication without incurring heavy AI operational costs. The hybrid Notion API + MCP approach ensures both speed for routine structured queries and coverage for complex, free-form content.

Summary of Changes

Changes from the previous proposal version to this updated version (v2):

1. Tech Stack Corrections

  • Discord library corrected to discord.py: The previous version listed Discord.js (JavaScript). The finalized stack uses discord.py (Python) consistent with the Python backend.
  • FastAPI removed from MVP scope: FastAPI is not needed for bot functionality — discord.py connects outward to Discord via WebSocket with no inbound HTTP server required. FastAPI is added back in the production deployment phase for health monitoring and future admin APIs.
  • LLM finalized as Google Gemini 2.0 Flash: OpenAI GPT / GPT-4o-mini removed. Gemini 2.0 Flash is the finalized model for its cost-to-quality ratio and bilingual support.
  • Notion MCP Server added: The previous version only listed Notion API. The finalized architecture uses a hybrid: Notion API for structured data (Tier 1/2) and Notion MCP Server for unstructured pages such as credentials, design docs, and free-form notes (Tier 3).

2. Terminology Fix

  • "RAG pipeline" replaced with accurate description: The system does not use Retrieval-Augmented Generation (which implies vector embeddings and semantic search). It uses direct Notion API querying for structured data and LLM-navigated MCP page reading for unstructured content. The updated proposal uses this accurate description throughout.

3. Feature Additions

  • Direct Message (DM) support added: Users can query the bot privately via DM without @mentioning it in a channel. Access is gated by Discord server membership verification to restrict usage to Timedoor staff.
  • Credential partial reveal policy added: Explicitly documented — host/URL shown, sensitive fields (passwords, tokens, API keys) never appear in Discord, full credentials link to Notion appended.
  • Bilingual support and stateful session context added: Bot detects and responds in the user's language (Indonesian/English); retains 3–5 exchange history per session with 30-minute timeout.

4. MVP Success Criteria Updated

  • Split response latency targets: Structured queries < 7 seconds; unstructured/MCP queries < 15 seconds.
  • Accuracy targets split by data type: ≥ 90% for structured data, ≥ 70% for unstructured/MCP content.
  • Monthly LLM cost target added: < $10 USD/month as a formal success metric.

5. Risk Updates

  • Risk 4 updated to Unauthorized DM Access: Reflects the newly added DM feature and the security control (server membership check) that prevents external users from accessing internal Notion data via DM.

6. Out of Scope Updated

  • FastAPI HTTP server, slash commands, and proactive alerts explicitly added to the out-of-scope table for clarity.
